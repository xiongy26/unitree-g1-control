# 新增 LIPM-ZMP 线性 MPC 控制模式（与现有 ZMP 预观控制并存可切换）

## 目标

在现有控制管线中，把 CoM 轨迹生成这一级做成可切换的两条实现：

```
足步规划器 GaitPlan（不变）
   → CoM 轨迹生成：【ZMP 预观控制 (OnlinePreview)】或【LIPM-ZMP 线性 MPC (MpcPreview·新增)】
   → 加权全身 IK（不变）→ 位置执行器（不变）
```

ZMP 模式行为保持逐字节不变；新增 MPC 模式经无头仿真验证后交付。

## MPC 公式（x/y 两轴解耦，经典 Wieber/Herdt 形式）

- **模型**：cart-table 状态 X=[c, ċ, c̈]，jerk 输入 u，离散化 A/B 与现有代码完全同构（controller.js:198 已有同款），采样 dt_mpc=0.02s
- **预测时域**：N=80（1.6s，覆盖 2 个整步态周期）
- **预测 ZMP**：p = c − (zc/g)·c̈，堆叠为 P = Pc·X0 + Pu·U（Pc N×3、Pu N×N 下三角，构建时算一次）
- **代价**：J = q_zmp·Σ(p_k − p_ref,k)² + r·Σu_k²，p_ref 逐点采样 `plan.zmpRef(tPlan + k·dt_mpc)`；zc 用 settle 实测的 `this.zc`
- **约束**：l_k ≤ p_k ≤ u_k——每个预测时刻由 `plan.phaseAt` 查相位：SS 取支撑脚矩形、DS/init/final 取双脚凸包（box）；脚底几何 x∈[−0.05, 0.12]、y 半宽 0.03（models/g1_walk.xml），留 margin 默认 0.015m
- **求解器**：OSQP 式 ADMM（自实现，无依赖，~100 行）。H=2(PuᵀQ Pu + rI) 恒定 → 构建时做一次 LDLᵀ/Cholesky 分解复用；每周期只迭代 ≤60 次稀疏向量运算，单次求解微秒级，62.5Hz 控制频率下毫无压力
- **指令输出**：从优化轨迹上取 t + mpcCmdLead（默认 0.03s，无头调参定）处的 CoM 位置，作为 `this.comTarget` 喂给现有 IK——MPC 的速度/加速度前馈隐含在轨迹采样点里

## 文件改动

1. **web/js/controller.js**（核心）
   - 新增导出类 `MpcPreview`，duck-type `OnlinePreview` 的对外接口：`planAt(t)`（临界阻尼 LIPM 名义 CoM 轨迹，构建时预计算——供 `updatePlanClock` 与 sim_node 记录使用）、`solve(t, pos, vel, acc)`（从实测状态滚解 QP）、`trajAt(tau)`（采样优化轨迹）
   - `settle()` 第 383 行分支：`this.preview = p.controller === 'mpc' ? new MpcPreview(gains, plan, plan.tEnd, p) : new OnlinePreview(...)`
   - `comTargetUpdate()`（458-540 行）增加分支：MPC 路径 = 状态估计（共享现有代码）→ `mpc.solve(...)` → `trajAt(mpcCmdLead)` → 写 `comCmd/comTarget`。ZMP 路径原样保留
2. **web/index.html**：`#ctrl` 面板（66-69 行旁）加 `<select id="in-ctrl">`：`zmp`（默认）/`mpc` 两项
3. **web/js/main.js**：`resetSim()` 仿照现有 4 个输入读取 `in-ctrl` → `params.controller`；状态栏文字带上当前控制器
4. **scripts/sim_node.mjs**：加 `--ctrl zmp|mpc` 及 MPC 调参标志（`--mpcdt --mpchor --mpcq --mpcr --mpcmargin --mpclead`）；`record()` 读的 `ctrl.preview.planAt(t)` 在 MpcPreview 上可用，其余不变
5. **README.md**：管线图更新为双模式；新增 MPC 章节（公式、QP、ADMM、参数表、验证包络）

不改动：models/g1_walk.xml、export_web_model.py、gains.json（MPC 只用其中 zc=0.685/g）、viewer.js、下游 IK 全部代码。

## params 新增（含默认值）

```js
controller: 'zmp',
mpcDt: 0.02, mpcHorizon: 1.6, mpcQZmp: 1.0, mpcR: 1e-5,
mpcFootMargin: 0.015, mpcCmdLead: 0.03, mpcAdmmIters: 60,
```

步态时钟 `updatePlanClock` 不改动（planAt 提供名义轨迹，clockGain=2 继续生效）；触地重定时保留。

## 验证（node 无头 harness，与浏览器同一 controller.js）

1. **回归**：`node scripts/sim_node.mjs`（默认 ZMP 模式）仍 VERDICT: PASS，行为不变
2. **MPC 主用例**：`node scripts/sim_node.mjs --ctrl mpc`（默认 16 步 × 0.12m）→ 调 mpcCmdLead/权重/margin 至 PASS（不跌倒、走完全程）
3. **包络扫描**：steps∈{8,16}、len∈{0.10,0.12}、ss∈{0.3,0.4,0.5} 双模式对比，输出跟踪误差与 CoP 误差表
4. 更新 README 的"已验证稳定步态包络"章节（ZMP / MPC 各一列）
5. 浏览器端 `py scripts/serve_web.py` 可启动，下拉框切换后点"重置"生效（逻辑与现有参数一致，风险低）

## 风险与对策

- **位置接口无前馈**：MPC 是加速度级规划，IK CoM 任务只吃位置 → 用 mpcCmdLead 采样点 + 现有 servoComp(0.7) 滞后补偿，无头仿真定参
- **SS 横向支撑域窄（y≈±0.015m）**：ADMM 对越界约束优雅降级（返回最小违反解），margin 可调；必要时放宽 SS margin
- **触地重定时引起参考跳变**：QP 每 16ms 从实测状态重解，参考经 smoothstep 过渡，指令天然连续
